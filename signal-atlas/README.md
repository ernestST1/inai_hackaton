# Эфир — карта покрытия Бишкека

Откройте **dist/index.html** в современном браузере. В автономную карту встроены Leaflet, шрифты, улицы Бишкека и результат расчёта по набору участников **data/07_coverage**. Готовый **dist/result.json** совпадает по всем полям с открытым эталоном **expected.json**. Эталон используется в тесте, расчёт читает только три CSV и параметры района.

Из 5 000 строк принято 4 800. Замеры попали в 398 ячеек, из них 387 прошли порог в пять замеров. Полный перебор 120 пар выбрал C09 и C14 с охватом 111 из 174 слабых ячеек. Жадный выбор C16 и C17 охватывает 108. Набор участников описывает синтетическую модель района Бишкека.

## Проверка жюри

Из папки `signal-atlas` выполните команду с Node.js 20 или новее. Для этой проверки достаточно файлов из архива.

```sh
node --test test/reference.test.js
```

Тест пересчитывает набор участников из трёх CSV и `bounds.json`, сверяет четыре поля ответа с `expected.json` и проверяет данные автономной карты. Команда `node --test` дополнительно проверяет границы диапазонов, дубликаты, равные медианы, радиусы и жадный алгоритм.

Чтение кода удобно начать с функции [analyze()](src/analysis.js). Её вызывают и браузер, и консольная команда.

| Что проверять | Где смотреть |
| --- | --- |
| Очистка, время и ключ дубликата из четырёх полей | [input.js](src/input.js) — `cleanMeasurements` |
| Границы района, шаг сетки и расстояния в метрах | [geo.js](src/geo.js) — `gridFor`, `haversine` |
| Медиана, минимум пяти замеров, цвета и порядок худших ячеек | [cells.js](src/cells.js) — `groupByCell`, `summarizeCells` |
| Отступ от БС, охват без повторов и выбор пары | [planning.js](src/planning.js) — `markEligibleSites`, `coveredByPair`, `exhaustivePair`, `greedyPair` |
| Расчёт за день и ночь, формирование `result.json` | [analysis.js](src/analysis.js) — цикл по `PERIODS` и объект `result` |
| Тепловая карта по медианам учтённых ячеек | [heat.js](src/heat.js) — `interpolateRsrp`, `renderBlock` |

## Расчёт на другом наборе

### В браузере

1. Нажмите **Загрузить CSV**, выберите три CSV и приложенный **bounds.json**. Можно также взять параметры текущего набора или ввести четыре границы вручную в градусах WGS 84.
2. Нажмите **Построить карту**. Кнопка **Скачать JSON** сохраняет результат для полного периода. Во вкладке **Данные** можно сохранить автономную HTML-карту с загруженным набором.
3. Выберите **Полный перебор** или **Жадный выбор** над картой. Маркеры, радиусы 1 км и карточка охвата переключаются вместе. Контуры слабых ячеек показывают пересечение и разницу двух пар. Нажатие на ячейку показывает медиану, число замеров и ID покрывающих её площадок выбранной пары.
4. В меню **Слои** включите **Запретные зоны 500 м**. Появятся круги вокруг существующих БС и точки отклонённых площадок. Нажмите на станцию, чтобы увидеть ID площадок в её зоне. Для сравнения по времени выберите день или ночь.

Расчёт выполняется локально. Базовая подложка встроена для центра Бишкека. Для улиц за пределами этого фрагмента доступен дополнительный онлайн-слой OpenStreetMap. Сетка и результаты вычисляются для любых введённых границ района.

### Из командной строки

Нужен Node.js 20 или новее. Готовая сборка позволяет обрабатывать новые CSV без установки пакетов. Выполняйте команды из корня проекта.

```powershell
node scripts/analyze.mjs --data data/07_coverage --out output
```

Для другого набора положите три CSV в одну папку. Передайте границы одним из двух способов.

```powershell
node scripts/analyze.mjs --data "C:/dataset" --bounds "C:/dataset/bounds.json" --out "C:/result"
node scripts/analyze.mjs --data "C:/dataset" --bounds "42.84,74.56,42.87597286423675,74.60905912302184" --out "C:/result"
```

Координаты во второй команде относятся к набору участников и перечислены в порядке **юг, запад, север, восток**. Без аргумента `--bounds` программа читает `bounds.json` из папки с CSV. При успешном расчёте в выбранной выходной папке появляются `index.html` и `result.json`.

## Входные файлы

| Файл | Обязательные поля |
| --- | --- |
| measurements.csv | lat, lon, rsrp_dbm, timestamp |
| towers.csv | id, lat, lon |
| candidates.csv | id, lat, lon |
| bounds.json | lat_min, lat_max, lon_min, lon_max. Параметры сетки — grid_origin_lat, grid_origin_lon, cell_size_m, earth_radius_m, timezone. Также поддерживается запись границ через south, west, north, east |

CSV читаются в UTF-8, включая BOM. Поддерживаются запятая, точка с запятой и табуляция, кавычки и дополнительные столбцы. Идентификаторы площадок сохраняются как строки. Ошибка в таблице станций или площадок останавливает расчёт и указывает номер проблемной записи.

Перед открывающей кавычкой допустимы пробелы. В таблице замеров повреждённые записи попадают в счётчик отброшенных. При незакрытой кавычке в числе или времени разбор продолжается со следующей строки. Дополнительное текстовое поле может содержать переносы внутри кавычек.

## Правила расчёта

- Каждая строка замеров исключается максимум один раз. Причины проверяются в порядке: повреждённые числа или число полей, RSRP вне включительного диапазона [−140, −44], координаты вне включительных границ, неверное время, дубликат. Дубликаты определяются по всем четырём полям после нормализации чисел и времени.
- Начало сетки задают grid_origin_lat и grid_origin_lon. Широта начала должна быть ≤ южной границы, долгота — ≤ западной. При ручном вводе четырёх границ за начало берётся юго-западный угол. Масштаб долготы определяется на широте начала сетки. Набор использует радиус Земли 6 371 000 м и шаг 200 м. Северный и восточный края входят в последние ячейки района.
- Для каждой ячейки берётся медиана. При чётном числе значений это среднее двух центральных. Ячейки с 1–4 замерами исключаются из дальнейшего анализа. Их валидные замеры остаются в статистике принятого набора.
- Зелёный цвет соответствует RSRP ≥ −90, жёлтый — диапазону от −105 включительно до −90 исключительно, красный — RSRP < −105 дБм.
- Три худшие ячейки упорядочены от меньшей медианы к большей. При равенстве выбирается меньший индекс строки, затем столбца. Формат ID — `X006_Y013`, где X растёт к востоку, Y — к северу, отсчёт с нуля. В JSON для каждой ячейки записаны `cell_id` и `rsrp_median`. Координаты центра и число замеров видны на карте.
- Все расстояния для выбора площадок вычисляются по формуле гаверсинусов. Площадка допустима при расстоянии не менее 500 м до каждой существующей станции. Ячейка покрыта, если её центр находится не далее 1 000 м от площадки. Считается мощность объединения двух множеств слабых ячеек.
- Перебираются все неупорядоченные пары различных допустимых площадок. При равном максимуме выбирается лексикографически первая пара ID. При отсутствии пары результат содержит пустой список и нулевой охват. При двух доступных площадках и отсутствии красных ячеек возвращается пара с нулевым охватом.

## Бонус

Во вкладке **Аналитика** приведены выбранные площадки, охват обоих алгоритмов, количество проверенных пар и разница в числе покрытых ячеек. Жадный выбор максимизирует охват первой площадки, затем дополнительный охват второй.

На карте набора участников обе пары покрывают 83 общие слабые ячейки. Ещё 28 покрывает только C09 + C14, а 25 — только C16 + C17. Разница в суммарном охвате составляет три ячейки. Смена периода пересчитывает эти множества.

Днём считается промежуток с 06:00 до 18:00 по времени Бишкека (UTC+6), ночью — остальные часы. Для каждого периода заново рассчитываются медианы, порог в пять замеров, распределение классов, тройка худших и лучшая пара. Время ISO 8601 со смещением приводится к местному. Время без смещения читается как местное. Поддерживаются Unix-время в секундах и миллисекундах.

Тепловая карта сглаживает медианы соседних ячеек билинейной интерполяцией с учётом доступных соседей. Пустые ячейки остаются прозрачными. Точное значение можно посмотреть нажатием на ячейку. Экспорт и выбор площадок используют исходные медианы.

Для поля `timezone` в `bounds.json` допустимы `Asia/Bishkek`, `UTC+6` и `+06:00`. В поле `timestamp` смещения `+0600` и `+06:00` равнозначны.

## Интерфейс и сборка

| Путь | Назначение |
| --- | --- |
| src/csv.js | Чтение CSV, обработка кавычек и проверка заголовков |
| src/map.js, src/heat.js | Слои Leaflet, станции, площадки, радиусы и тепловая карта |
| src/app.js, src/views.js, src/icons.js | Загрузка файлов, экспорт, навигация и представление результатов |
| src/format.js | Числа для интерфейса и экранирование текста для HTML |
| src/page.html, src/style.css | Разметка и адаптивное оформление |
| scripts/analyze.mjs, scripts/report.mjs | Консольный расчёт и создание автономного отчёта |
| scripts/build.mjs, assets/dashboard.js | Сборка и готовый браузерный код |
| data/07_coverage | Предоставленный набор, параметры сетки, описание организаторов и эталон для проверки |
| scripts/demo.mjs, data/demo | Воспроизводимый синтетический набор из 5 000 строк и 20 площадок |

После изменений интерфейса пересоберите браузерный код и отчёт по набору участников.

```powershell
npm ci
npm run format:check
npm run build
npm test
```

Команда `npm run format` применяет Prettier к исходникам интерфейса и скриптам. Команда `npm run demo` восстанавливает дополнительный пример в `data/demo` с фиксированным зерном генератора. Команда `npm run build` собирает отчёт по основному набору `data/07_coverage`.

## Лицензии и геоданные

Станции, площадки и радиозамеры в примере синтетические. [OpenStreetMap и ODbL](https://www.openstreetmap.org/copyright) · [OpenFreeMap](https://openfreemap.org/) · [OpenMapTiles](https://openmaptiles.org/)

Источник — снимок OpenFreeMap `planet/20261115_080022_pt/13/{x}/{y}.pbf` на `tiles.openfreemap.org`. Подготовленная подложка уже включена в `assets/bishkek.svg`.
